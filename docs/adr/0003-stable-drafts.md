# ADR-0003：稳定草稿、版本冲突与副本恢复

日期：2026-10-22 · 对应任务：CW-004 · 状态：实现完成，自动化与浏览器验证通过；完整桌面退出重启 UI 验收待补。

## 问题与决策

原草稿只保存在浏览器 localStorage，Electron 每次启动随机端口使旧稿不可见；两个窗口还可能写入同一缓存键而相互覆盖。采用当前本机资料库作为权威保存位置，以稳定 storeId 和草稿位置识别内容，以 revision 条件更新解决并发。浏览器缓存只保护尚未提交的窗口输入，不自动覆盖资料库。

不固定桌面端口，不给渲染进程开放文件读写桥接，不在冲突时自动拼接文字。这样 Web 与桌面共用仓储、API 和界面，授权边界仍是既有本地服务。默认 Web 与桌面使用不同目录，不提供跨设备同步。

## 数据与格式版本

| 项目                   | 当前版本/规则                                                 |
| ---------------------- | ------------------------------------------------------------- |
| 数据库                 | 2；SQLite DELETE 日志、FULL 同步、独立 worker、目录唯一写入权 |
| 草稿格式               | 2                                                             |
| 能力契约               | 3；storage.drafts=server-sqlite                               |
| State / 会话 JSON 备份 | 1，结构保持兼容，备份不含草稿                                 |
| 浏览器 v1 草稿         | 只读取为恢复候选，不自动覆盖资料库                            |

`drafts` 保存 owner_key、revision、text、attachments_json、updated_at。正文和文本附件仍为本机明文。未创建记录返回空稿和 revision=0，首次保存得到 1；每次写入递增，清空也保存空稿与递增版本，不删除版本历史位置。数字受安全整数边界限制。

`draft_recoveries` 保存 id、owner_key、revision、正文、附件、内容 SHA-256 与时间。按位置和内容哈希去重，按时间倒序读取。副本不是逐键输入历史，也没有无限期保存的产品承诺；当前没有分页、容量上限或清理 UI，后续须补管理策略，不能静默丢弃副本。

## v1 → v2 数据库升级

1. 获得资料目录写入权，检查文件头、已知版本和日志模式；让兼容版本恢复已有 hot journal。
2. 检查完整性、原业务结构及 storeId 与标记/迁移计划一致。
3. 开始 IMMEDIATE 事务取得数据库写锁。在任何修改前读取主库字节，写入 `state.sqlite.backup-v1-<sha256>`；已有同名备份核验哈希。备份使用私有只读权限，完成文件与目录持久化。
4. 创建 drafts、draft_recoveries，并设置 user_version=2；同一事务提交。失败回滚并保留备份。新目录直接创建 v2。
5. 检查所需草稿表列存在；API 读取还执行内容 schema 校验。没有把所有草稿正文在启动时完整扫描一遍。

已有 SQLite v1 的加表升级会在启动时自动进行，原 JSON → SQLite 的首次迁移仍须显式入口。storeId、原历史和旧备份保留。未知未来版本不会被尝试升级。v1 程序不能继续打开 v2 活动目录。

回退只能在所有写入程序停止后，对备份复制品使用兼容版本，并保留当前目录；v1 备份不包含升级后的新消息和草稿，不提供无损降级。不要删除激活标记、迁移计划或崩溃日志来强制初始化。这里只提供升级时备份，不是持续全库备份产品。

## API 与并发事务

统一前缀 `/api/v1/drafts`，所有响应 `Cache-Control: no-store`。除 GET `/identity` 外，须携带匹配的 `X-ChatWorker-Store`。缺少或不匹配身份返回 409 `STORE_CHANGED`，不把输入写入其他资料库。

| 方法和路径            | 输入 / 结果                                                                |
| --------------------- | -------------------------------------------------------------------------- |
| GET /identity         | storeId、version=2                                                         |
| GET /:key             | key、revision、updatedAt、draft                                            |
| PUT /:key             | expectedRevision、draft、可选 preservePrevious；200 或 409 返回 ok/current |
| GET /:key/recoveries  | 此位置的恢复副本数组                                                       |
| POST /:key/recoveries | revision、draft；保存非空副本，不改变当前稿                                |

PUT 开始事务后读取当前版本。相符时，按需先保存当前稿的恢复副本，再写入新稿和递增版本，一起提交；不相符时，先将被拒绝的非空输入保存为副本，再提交并返回 409 和当前稿。因此，版本冲突响应也可能新增恢复副本。副本保存失败则整笔回滚、返回错误，不假装已经保存。

所有 SQL 都绑定参数。所属位置删除返回 404；内容格式错误返回 400。历史全量写入不重建草稿表，只在会话或项目删除时清空对应非空稿并增加版本、删除其资料库恢复副本。项目下已有会话保留为独立会话，所以会话草稿保留。其他窗口中已有的缓存不被远程强制擦除。

## 客户端状态与响应顺序

状态为 loading → saved → dirty → saving → saved；网络/存储失败进入 offline，版本不相符进入 conflict。加载完成前不接受新输入，避免用空白占位稿覆盖尚未读到的版本。

每次编辑增加本地 epoch，先写本窗口缓存，再等待约 400 毫秒提交。每个位置的写操作串行：请求中继续输入时，旧响应只更新版本号，随后保存新内容，不能把旧正文写回输入框。读取记录启动时的 revision 和 epoch，任一变化或正在写入时忽略旧读取结果及错误。

当前可见输入区每五秒、重新获得焦点或网络上线时刷新。无本地修改的窗口采用最新稿；有本地修改且版本变化时比较两个版本。此机制是轮询和显式冲突处理，不是实时协同编辑或 CRDT。

本地缓存键包含 storeId、位置和随机窗口 ID，同一浏览器中的两个窗口不会互相覆盖缓存。缓存格式损坏时保留原条目并告知用户；容量不足时保留内存稿、显示警告，服务保存仍可继续。只有收到服务提交成功才显示“已保存到本机”。页面隐藏/退出触发尽力保存，不能保证退出瞬间的网络请求完成。

## 冲突选择与恢复

- 保存本窗口版本：再次以已观察的远端 revision 条件写入，事务内保存被替换稿。如果第三个窗口又修改，仍返回冲突，绝不强制覆盖。
- 采用已保存版本：先把当前窗口稿归档到服务端，再更新输入区。归档失败保留原内容；等待期间用户继续编辑则放弃旧选择。
- 比较并恢复：恢复列表合并资料库副本、当前地址的各窗口缓存和可读的 v1 草稿。选择某个副本先进入比较状态，不直接写库；比较期间继续编辑后切换副本，会保留刚编辑的内容。
- 下载两个版本：生成 `chatworker-draft-copy` v1 JSON，含本窗口稿和当前已观察到的保存稿。用于人工保留，尚无文件导入入口，不等于现有会话备份格式。

客户端缓存副本受浏览器 origin 限制。服务端已提交的稿和恢复副本可跨端口读取；另一个端口下未提交的旧缓存无法自动找回。不能把“跨端口恢复已保存稿”描述为“任何退出都不会丢最后一个字符”。副本列表目前也没有删除操作。

## 发送、转存与清空

发送先 flush，取得包含正文/附件、revision、epoch 的回执。新会话创建后，先在目标位置保存，再按源回执尝试清空原位置；目标保存失败保留原稿。消息被服务接受后，只在回执与当前本地代次、版本、内容全部相符时发起条件清空。其他窗口改动会使清空请求冲突，旧响应不能删除新内容。

消息接受、草稿转存和清空是多个事务，当前没有共同的幂等请求键。响应丢失可能留下已发送草稿或已创建空会话；界面不自动重发。CW-005 负责后续统一接受事务与重复请求语义，CW-006/007 再加入事件恢复和独立运行。

## 验证证据与边界

[验证记录](../verification.md) 包含自动化、浏览器与存储运行时结果：版本竞争、陈旧清空、丢响应、旧读取、保存中继续编辑、不同资料库隔离、缓存容量失败、显式 v1 恢复、转存失败、删除上下文、升级字节备份及事务回滚。
