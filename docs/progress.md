# ChatWorker 项目进度

更新：2026-10-22 · 口径：以当前代码和已执行验证为准。架构目标见 [整体蓝图](agent-architecture-blueprint.md)，实际行为见 [设计文档](design.md)，证据见 [验证记录](verification.md)。

## 当前结论

ChatWorker 已能作为本机运行的 Vue Web / Electron 聊天工作台使用，支持自行配置模型服务、流式聊天、项目与会话整理、文本附件和备份。SQLite 可靠保存基础已接入，本轮加入稳定草稿和多窗口冲突恢复。尚未实现通用智能体所需的独立任务运行、工具循环、权限审批、文件修改和命令执行。

不以一个未经工作量估算的百分比描述全项目。首批十项开发任务中，CW-001～003 已完成本机验收，CW-004 已实现并通过主要验证但仍需完整桌面退出重启 UI 验收，CW-005～010 待实现。4/10 只代表这批任务的实现数量，既不是整个项目 40%，也不是发布完成度。

## 本轮交付：CW-004

1. 草稿内容与文本附件进入 SQLite v2，同一资料库的已保存稿不再受随机端口影响。
2. 多窗口条件更新；发生冲突时保留两个版本并提供比较、选择、下载和副本恢复。
3. 本窗口缓存按独立窗口区分；离线、容量不足、旧缓存和另一个资料库的内容不会静默覆盖已保存稿。
4. 保存中继续输入、旧读取、旧消息接受回调都有版本/编辑代次保护；新会话先转存再清空源稿。
5. v1 数据库升级先生成 SHA-256 命名的原字节备份，加表与版本号一起提交，失败回滚。
6. 能力页和文档同步真实状态，保留现有会话 JSON 备份兼容性。

边界：消息接受与草稿清除仍是多个事务；响应丢失可能留下已经发送过的草稿。副本尚无清理和分页，草稿不包含在现有会话备份中。完整 GUI 重启和正式应用重新打包尚未完成，存储运行时检查不替代这两项。

## 接下来的实施顺序

1. **CW-005：Run 接受事务和幂等键。** 将用户输入、Run、幂等记录作为一个接受动作；相同键和内容返回同一结果，不同内容拒绝；模拟接受响应丢失后重试。
2. **CW-006：事件日志、快照与 SSE 重连。** 先落关键事件再发送，游标去重，明确过期与缺口行为。
3. **CW-007：运行独立于页面。** 页面关闭、取消竞态、服务重启和恢复界面分别定义并验证。
4. **CW-008/009：只读工具闭环。** 三类模型协议工具事件、参数校验、限定工作目录的读取/搜索与引用。
5. **CW-010：受控写入试验。** 在前述闭环稳定后引入差异、批准、补丁和副作用恢复。

在进入工具执行前补齐 P0/P1 剩余验收；发布时用相同提交重新构建完整应用并记录版本。每轮实现、验证、更新文档、提交并推送；未经验证的规划继续标为待实现。
